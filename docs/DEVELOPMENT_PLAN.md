# 中后台前端模板开发计划

## 项目目标与现状

将项目建设为可直接用于新业务的中后台前端基础模板：封装完整布局、常见页面和通用组件，通过清晰的接口适配边界接入后端 API，减少搭建 VP 时重复开发的工作。

当前已有 React、TypeScript、Vite、Ant Design、React Router、TanStack React Query、Axios 和 Zustand 依赖，启用了 React Compiler，并具备 lint、类型检查和构建命令。源码仍为初始演示页面，布局、业务路由、认证、接口层和业务组件尚未建设。依赖已安装不代表能力已实现。

首版优先覆盖桌面中后台场景，同时保证窄屏下导航、表单和主要操作可用。以通用 CRUD 业务为验证样例，不提前实现复杂行业业务。

## 开发顺序与里程碑

按 P0 到 P5 顺序推进，每阶段验收后进入下一阶段。每阶段拆成可独立检查的改动，避免一次提交整套框架。

| 阶段 | 目标 | 主要交付物 | 完成标志 |
| --- | --- | --- | --- |
| P0 工程基础 | 建立可扩展的应用入口 | 应用级 Provider、目录边界、配置及主题入口 | 开发、检查、构建正常，应用基础配置集中 |
| P1 布局与路由 | 形成可导航的中后台骨架 | 应用布局、菜单、面包屑、路由元信息、异常页面 | 导航、刷新、直达链接与窄屏布局可用 |
| P2 认证与 API | 打通前后端业务链路 | 请求层、认证、权限、演示接口适配、首个列表闭环 | 登录后可查询及修改数据，异常和会话失效可处理 |
| P3 通用组件 | 提炼常见业务交互 | 页面容器、查询列表、表单弹窗、权限及状态组件 | 示例页面组合组件即可完成常见 CRUD |
| P4 页面模板 | 提供可复制的业务范例 | 工作台、列表、表单、详情、设置及组件示例 | 页面可复制扩展，示例业务可移除 |
| P5 验证与交付 | 确认可作为新项目起点 | 接入文档、配置示例、验证记录、模板清理说明 | 新业务按文档接入一组 API，无需修改基础框架 |

## P0：工程基础

交付内容：

- 建立应用初始化与 Provider 入口，集中组织 Ant Design 主题、React Query 配置和路由。
- 按实际需要建立 `layouts`、`routes`、`services`、`stores`、`config` 等目录，补充目录职责约定。
- 配置 `@/` 路径别名，同步 TypeScript 与 Vite，更新开发规范中的现状说明。
- 定义应用名称、默认首页、主题等配置入口；提供 `.env.example`，说明 API 基础地址、开发代理和演示模式配置。
- 明确配置来源、环境变量可见性和私有配置忽略规则；整理全局基础样式，逐步替换 Vite 示例内容。

验收标准：`pnpm dev` 可启动，`pnpm lint`、`pnpm build` 通过；新增配置有类型和文档，启动不依赖真实后端或私有凭据。

## P1：布局与路由体系

交付内容：

- 默认应用布局包含侧边菜单、顶部导航、用户区域、面包屑和内容区；支持侧栏折叠与窄屏抽屉导航。
- 独立认证布局，用于后续登录页面。
- 统一维护路由元信息，包括标题、图标、排序、菜单可见性、布局类型和权限标识；菜单与面包屑从路由配置派生。
- 支持嵌套路由、页面懒加载、加载反馈、默认重定向和路由级错误兜底。
- 提供 403、404、500 页面及返回首页等恢复操作。需要真实后端支持的状态在后续阶段接入。
- 统一文档标题、菜单选中与展开规则。

验收标准：侧栏点击、浏览器前进后退、刷新深层路径、未知地址均有正确表现；动态参数和隐藏菜单页面的面包屑正确；布局在窄屏无关键操作丢失。部署文档记录 SPA 路由回退要求。

## P2：认证、权限与 API 接入

先完成一条“登录 → 进入列表 → 查询 → 新建或编辑 → 刷新数据”的纵向链路，再提炼通用组件。

交付内容：

- Axios 请求实例统一管理基础地址、超时、认证信息、请求取消和错误分类。
- 在接口层定义分页参数、分页结果、用户及权限模型，通过适配函数转换具体后端结构；不要求后端强制采用模板定义的响应包裹格式。
- 统一处理网络失败、业务失败、401 和 403，明确全局与页面提示分工，避免重复提示。
- 实现登录、退出、获取当前用户、会话恢复和受保护路由；登录成功可安全返回原页面，退出时清理用户相关缓存。
- 约定认证扩展点，文档说明 token 或 cookie 认证如何接入。是否接入刷新机制由后端能力决定，不提前假定刷新接口存在。
- 路由与按钮权限共用权限判断入口，未授权地址可正确拦截。前端权限用于交互控制，数据授权由后端执行。
- 使用 React Query 管理查询参数、分页、加载、缓存与变更后刷新，提供一个完整列表业务作为后续抽象依据。
- 提供独立、可切换的演示数据适配层，演示数据不散落在页面中；真实接口模式配置缺失或失败时明确报错，不静默回退到演示数据。

验收标准：正常登录、登录失败、刷新恢复、会话过期、退出、越权访问均有明确结果；列表覆盖加载、空数据、分页、查询失败和提交失败；写操作防重复提交。切换接口适配后，页面无需重写，用户间缓存不串用。

## P3：通用业务组件

基于 P2 实际页面提炼，优先采用组合与明确的 props；保留 Ant Design 原有能力，避免首版引入庞大的配置 DSL。

查询列表以[列表页样式规范](LIST_PAGE_STYLE.md)为验收依据，先在用户管理页落地，再提炼共用结构。

交付内容：

- 页面容器：统一标题、说明、操作区和内容间距。
- 查询列表：组合筛选、重置、表格、分页、刷新及批量操作，允许业务自定义列与操作区。
- 弹窗与抽屉表单：统一打开、回填、校验、提交反馈和关闭行为。
- 常用展示与交互：状态标签、详情区块、危险操作确认及加载、空白、错误状态。
- 权限组件与 hook：复用 P2 的权限判断能力。
- 为公共组件提供类型、默认行为、最小示例和边界说明，标明受控状态的归属。

验收标准：已有列表业务迁移后交互不退化；新增相似页面无需复制加载、分页和提交控制逻辑；重复打开表单不会残留上次数据，查询与分页联动正确，批量操作失败有反馈。

## P4：常用页面与示例体系

交付内容：

- 工作台：展示常用入口、统计卡片和最近活动，使用明确标识的演示数据。
- 列表页：提供标准 CRUD 示例，包含筛选、分页、状态展示和操作权限。
- 表单页：提供基础表单与分步表单示例，展示校验、回填和提交反馈。
- 详情页：提供分组信息、状态和操作记录的组合示例。
- 个人中心与偏好设置：展示当前用户信息、主题与布局偏好；未接入保存接口的功能需明确为本地偏好或演示。
- 组件示例页：展示公共组件的常见使用方式与必要的代码示例。
- 提供统一的明暗主题切换和偏好持久化，保持组件及布局表现一致。

验收标准：每类页面有可运行的使用范例，所有可见按钮都有有效行为或明确状态；文案、间距、反馈方式一致；演示模块的入口和依赖清晰，可按文档移除。

## P5：质量验证与模板交付

交付内容：

- 开发指南：从安装启动到新增路由、菜单、权限、列表页面的完整步骤。
- API 接入指南：说明接口地址、认证、用户及权限、分页、响应适配和错误处理；包含从演示切换到真实接口的示例。
- 模板裁剪指南：说明如何替换品牌信息、移除演示页面、保留基础布局和业务组件。
- 部署说明：记录构建环境变量、静态产物部署、SPA 回退和接口跨域或代理配置。
- 验证核心流程、异常路径、键盘操作、窄屏表现及目标浏览器，记录实际结果与已知限制。
- 检查懒加载与构建产物，针对实际发现的性能问题优化，不预设无依据的性能数字。
- 用一个独立示例业务验证接入路径：仅新增接口适配、页面和必要配置即可完成业务，不修改公共请求层或布局内部逻辑。

验收标准：按文档可从干净安装完成启动和构建；演示与真实接口模式行为明确；关键业务链路通过验证，未完成内容明确列出，无需阅读框架内部源码即可新增一个常见业务页面。

## 首版范围与后续扩展

首版必需能力为 P0 至 P5 中的基础布局、路由、认证权限、API 适配、常用组件与页面、主题和接入文档。

以下作为后续独立需求评估，不阻塞首版：多标签页与页面保活、国际化、多租户、动态服务端菜单、复杂数据权限、可视化搭建、微前端、SSR，以及复杂图表、富文本和大文件上传。扩展前明确实际场景和依赖成本。

## 执行与验证约定

- 当前已进入 P2 的请求基础层。每个事项开始前说明做法与原因，获得用户确认后再修改代码。
- 每阶段交付后更新本文件的进度与已知问题，不以依赖安装或页面占位表示能力完成。
- 代码改动执行 `pnpm lint`、`pnpm build`，涉及交互时补充手动验证；简单功能不补充单测。
- 对权限判断、响应适配、分页转换和会话失效等复杂或易回归逻辑安排必要的自动化验证；引入测试工具时明确用途，不为简单页面搭建测试体系。
- P0 已完成应用入口、Provider、路径别名、应用基础信息、环境配置、开发代理和浅色主题。P1 的布局接入替换了 Vite 示例首页及样式。
- P1 已接入固定版本 `@ant-design/pro-components@3.1.15-9`。JustAdmin 管理导航数据及布局配置，`AdminLayout` 负责与 ProLayout 适配。布局设置抽屉支持实时切换三种导航、固定栏选项、侧栏宽度及定宽或流式内容，并在当前浏览器保存偏好。嵌套路由、面包屑、浏览器标题及 403、404、500 异常页已接入。
- P2 已建立 Axios 请求入口，统一 API 基础地址、10 秒超时、取消和错误分类。临时 HTTP 服务验证了成功响应、401、403、超时、网络中断及取消。`pnpm lint` 和 `pnpm build` 通过，认证与业务接口仍待接入。P3 至 P5 未开始。
- P2 已提供可选的开发 Mock 认证，覆盖登录、当前用户和退出。HTTP 联调验证了会话 Cookie、退出后会话失效、生产预览隔离和切回真实代理。
- P2 登录表单和后台业务路由守卫已接通 Mock。Chrome 验证了错误密码提示、防重复提交、登录后返回原地址、Cookie 会话恢复、网络重试和拒绝站外返回地址。`pnpm lint` 和 `pnpm build` 通过。
- P2 用户菜单与退出登录已接入。Chrome 验证了三种布局、折叠侧栏和窄屏入口，以及退出失败重试、成功后清理 Cookie 和缓存、浏览器后退及直达后台重新要求登录。`pnpm lint` 和 `pnpm build` 通过，构建仍有包体积警告。
- P2 菜单、路由和操作入口统一使用 `/auth/me` 的权限码。Chrome 验证了管理员与只读用户的菜单和详情入口差异、刷新恢复权限、直接访问受限地址跳转 403，以及退出后换账号的权限隔离。
- P2 用户管理列表与 `GET /api/users` Mock 已接入。页面按需加载，支持关键词、状态筛选和服务端分页。Chrome 验证了两个账号、筛选回第一页、分页总数、加载、空结果、失败重试和 390px 窄屏。未登录或退出后调用接口返回 401。新增、编辑和删除待实施。
